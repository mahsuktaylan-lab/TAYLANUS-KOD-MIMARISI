# TAYLANUS Engine for TAY Language

## Purpose

The engine bridge lets a `.tay` program configure and run the existing
TAYLANUS v3 incompressible-flow research core. It adds orchestration and
diagnostics; it does not replace or duplicate `taylanus_core.py`.

## Two independent choices

`BACKEND` and `ENGINE` answer different questions:

| Directive | Question | Values |
|---|---|---|
| `BACKEND` | Which array/device runtime executes ordinary TAY operations? | `NUMPY`, `TORCH`, `GPU` |
| `ENGINE` | Which domain solver executes this simulation? | `TAYLANUS` |

The released TAYLANUS engine accepts only the validated CPU path. A direct
adapter call with `backend="TORCH"` or `backend="GPU"` raises
`EngineError` before creating output and explicitly says that no silent
fallback occurred.

## Language form

```tay
BACKEND NUMPY
ENGINE TAYLANUS

RESOLUTION 32
DT 0.005
TEND 0.20
MODE AUTO
VISCOSITY 0.0033333333333333335
SLICE 16
PLANNER_REPS 3
REFERENCE "../references/localized_vortex_N32_t0p20.npy"
OUTPUT "../outputs/taylanus_vortex"

RUN TAYLANUS
```

The same directives work in the interpreter and in Python generated by
`compile_to_python`.

## Configuration

| Setting | Default | Validation |
|---|---:|---|
| `RESOLUTION` | 32 | 32 or 64, the v3 validated equivalent resolutions |
| `DT` | resolution default | positive; at most 0.005 for 32 and 0.0025 for 64 |
| `TEND` | 0.20 | positive, at most 0.20, integer multiple of `DT` |
| `MODE` | AUTO | AUTO, FAST, COMPACT, SUBFACE_SPARSE or MODAL_STREAM |
| `VISCOSITY` | 1/300 | finite and positive |
| `SLICE` | middle plane | integer inside the grid |
| `PLANNER_REPS` | 3 | integer from 1 through 20 |
| `REFERENCE` | NONE | optional compatible NumPy `.npy` velocity field |
| `OUTPUT` | outputs/taylanus_vortex | non-empty path, relative to the program |

The time horizon is deliberately fail-closed at the short-time v3 validation
envelope. Extending it is a scientific-validation change, not merely a parser
change.

## Execution flow

1. Validate all configuration before solver setup.
2. Set the existing core's resolution context.
3. Build the deterministic adaptive topology with
   `build_initial_topology`.
4. Reuse a resolution-specific `UnifiedCompileCache`.
5. Construct `UnifiedTaylanusIR`.
6. Select a representation:
   - AUTO calls the real `ir.plan`;
   - FAST/SUBFACE_SPARSE selects sparse subfaces directly;
   - COMPACT/MODAL_STREAM selects the local modal state directly.
7. Create and project the analytic initial state.
8. Advance only through `step_subface` or `step_modal`.
9. Reconstruct the final cell velocity using
   `cell_velocity_fast`.
10. Compute diagnostics and write reproducible data/figures.

The module-level viscosity required by the frozen core is changed inside a
process lock and restored in a `finally` block. This prevents overlapping
TAY runs from corrupting each other's core context.

## Returned values

After `RUN TAYLANUS`, the TAY environment contains:

| Name | Meaning |
|---|---|
| `CFD_RESULT` | complete JSON-safe diagnostics dictionary |
| `CFD_STATUS` | PASS on successful completion |
| `CFD_OUTPUT_DIR` | absolute output directory |
| `CFD_REPRESENTATION` | selected solver representation |
| `CFD_LEAF_COUNT` | adaptive leaf count |
| `CFD_STATE_DOFS` | selected-state degrees of freedom |
| `CFD_RMS_DIVERGENCE` | conservative RMS divergence |
| `CFD_MAX_DIVERGENCE` | conservative maximum absolute divergence |
| `CFD_KINETIC_ENERGY` | final mean kinetic energy |
| `CFD_REFERENCE_L2` | relative L2 error or NONE |

`CFD_RESULT` also contains compile/setup/planner/runtime timings, cache
hits/misses, subface DOFs, compression, energy endpoints, environment
versions, planner candidates and every output path.

## Output contract

`OUTPUT` receives:

| File | Source |
|---|---|
| `mesh_level_slice.png` | `geom.levels[geom.owner]` |
| `level_distribution.png` | adaptive leaf-level counts |
| `velocity_magnitude_slice.png` | reconstructed final velocity |
| `vorticity_magnitude_slice.png` | periodic central derivative of reconstructed velocity |
| `divergence_slice.png` | conservative face-flux divergence mapped from leaves |
| `kinetic_energy_history.png` | solver state at each time step |
| `kinetic_energy.csv` | numeric step/time/energy values |
| `diagnostics.json` | complete run record |
| `velocity_final.npy` | final 32³ or 64³ cell velocity |
| `mesh_levels.npy` | finest-grid view of leaf levels |
| `conservative_divergence.npy` | finest-grid view of leaf divergence |

The divergence figure uses the conservative face fluxes and leaf volumes, the
same physical quantity used by the core's divergence gate. It does not plot a
different cell-centered finite-difference estimate.

## Pressure-data policy

TAYLANUS performs pressure projection internally, but the v3 public result
does not expose a pressure field/history. The bridge therefore records:

```json
{
  "pressure_field_available": false,
  "pressure_plot_written": false
}
```

No synthetic pressure plot is created.

## Packaging

The combined `taylang` wheel includes:

- the `taylang` package;
- `taylang.engines.taylanus`;
- the existing top-level `taylanus_core` module.

SciPy and Numba are declared in the optional `taylanus` extra:

```bash
python -m pip install ".[taylanus]"
```

The Windows installer uses that form. There is no source-directory
`sys.path` injection.

## What this enables for fluid studies

The useful advance is not a new Navier–Stokes discretization. It is a clean
experiment layer over a frozen numerical core:

- parameter sweeps can be expressed as small, reviewable TAY programs;
- AUTO/FAST/COMPACT choices can be compared without changing solver code;
- every run produces a machine-readable provenance and diagnostic bundle;
- adaptive-grid, error, energy and divergence behavior can be inspected from
  the same source;
- a later batch/session layer can compare viscosity, resolution and
  representation while preserving fail-closed validation envelopes.

The next credible scientific extensions are additional reference flows
(Taylor–Green vortex, lid-driven cavity, channel flow), boundary-condition
generalization, long-time convergence studies, exposed pressure diagnostics,
and only then validated accelerator backends. Each extension needs its own
reference data and acceptance gates.

## Limits

- Short periodic localized-vortex validation only.
- Resolutions restricted to 32 and 64.
- TEND restricted to 0.20.
- Modal state compression is demonstrated; modal CPU speed superiority is not.
- No dynamic-topology language control is exposed.
- No pressure field output.
- No validated TAYLANUS GPU/Torch execution.
- No ANSYS equivalence or production-readiness claim.
